# Vector Radio

Мінімалістичне Windows-радіо з цифровим ведучим Адамом Вектором. Основний екран має лише логотип, центральне Play/Pause, поточний трек і шестерню. У видимих налаштуваннях залишені імпорт API TXT та жанр/стиль ефіру; розширені технічні параметри збережені в коді для сумісності.

## Windows Setup

Готовий інсталятор збирається командою:

```powershell
.\packaging\build_installer.ps1
```

Результат: `dist\Vector_Radio_Setup_1.0.0.exe`. Setup встановлює програму для поточного користувача, створює ярлик і деінсталятор, завантажує перевірений SHA-256 офіційний embeddable Python 3.11.9, локальний український StyleTTS2 з голосом Адама Вектора та WebView2 лише за його відсутності. Системний Python не змінюється. Для інсталяції потрібні інтернет і приблизно 3 ГБ місця. Повна інструкція й формат API-файлу: [`docs/INSTALL_WINDOWS.md`](docs/INSTALL_WINDOWS.md).

У корені є готовий статичний [`index.html`](index.html) для GitHub Pages або іншого хостингу. Його кнопка веде на останній Windows Setup у GitHub Releases.

Локальний Windows-прототип AI-радіо: плейлист у SQLite, локальне аудіовідтворення та український цифровий ведучий Адам Вектор із контекстом ефіру. DJ може паралельно порівнювати NVIDIA NIM і DeepSeek через OpenRouter. Кожен доступний AI типово створює по два варіанти підводки; незалежні перевірки правопису, маркерів, фактів і темпу оцінюють усіх кандидатів, а в ефір іде найкращий бал незалежно від назви провайдера. Репліки локально озвучуються українським StyleTTS2 і кешуються як WAV. Edge TTS (`uk-UA-OstapNeural`) та системний голос залишаються резервом. Якщо жоден AI-варіант не проходить перевірку, ефір озвучує коротку локальну підводку.

## Адам Вектор

Адам — відкрито цифровий музичний ведучий, а не імітація людини. Ядро його характеру — допитливість, точність і суха самоіронія: він має музичний смак, відділяє власну реакцію від факту, не приймає красиву легенду без джерела й повністю вимикає гумор на чутливих темах. Він не вигадує біографію, фізичний досвід, поїздки чи знайомства. Фінальна відповідальність за чутливий матеріал залишається за людиною-редактором.

Повний редакційний стандарт: [`docs/ADAM_VECTOR_PERSONA.md`](docs/ADAM_VECTOR_PERSONA.md). Повний аудит дослідження та пріоритетний беклог: [`docs/RESEARCH_IMPLEMENTATION_MATRIX.md`](docs/RESEARCH_IMPLEMENTATION_MATRIX.md).

## Пілотна година

Ефір працює за версіонованим clock `2026.08-pilot-v1`: 12 безперервних п'ятихвилинних сегментів, рівно `60:00`, із hard points на `:00`, `:15`, `:30` і `:45`. Кожна підготовлена репліка отримує повний rundown: тезу, hard time, джерела, verification status, вимову, entry/exit cues, CTA, fallback, forbidden claims і відповідального редактора. Запланований та фактичний час виходу зберігаються в SQLite, а UI показує актуальну сітку й відсоток потраплянь у допуск ±5 секунд.

Повна сітка й критерії 20 пілотних прогонів: [`docs/PILOT_HOUR_RUNDOWN.md`](docs/PILOT_HOUR_RUNDOWN.md).

## Безпека ефіру

Детермінований watchdog контролює локальний плеєр і TTS під час активного ефіру: попереджає про тишу через 2–3 секунди, а через 5–8 секунд пробує відновити поточний файл, перейти до наступного локального треку або озвучити технічну паузу. Ручна пауза оператора не запускає аварію. Кнопка `Виправлення` не дозволяє поставити корекцію в ефір без правильного формулювання, HTTP(S) джерела та відповідального редактора. Усі події зберігаються в SQLite.

Повний перелік станів, обмежень і журналу: [`docs/BROADCAST_SAFETY.md`](docs/BROADCAST_SAFETY.md).

## Запуск

```powershell
py -3.11 -m venv .venv311
.venv311\Scripts\pip install -r requirements.txt
.venv311\Scripts\python main.py
```

Python 3.12 рекомендований для майбутнього пакування; базовий прототип також працює на новіших версіях, якщо `pywebview` їх підтримує. WebView2 зазвичай уже встановлений у Windows 10/11.

NVIDIA API key читається з локального `api.txt` або з поля у «Налаштуваннях». Типова hosted-модель — `nvidia/nemotron-3-super-120b-a12b`. OpenRouter key із `api.txt` або налаштувань вмикає DeepSeek. Без доступного AI працюють локальний текст і каскад резервних голосів. YouTube Data API потрібен лише допоміжним скриптам перевірки каталогу, а не радіоплеєру.

Повна тестова бібліотека містить 423 композиції. Ефір використовує лише треки, для яких уже існує локальний аудіофайл.

Через денний і короткочасний rate limit YouTube перевірка виконується пакетами та продовжується з місця зупинки:

```powershell
.venv311\Scripts\python scripts\build_playlist.py --limit 90
```

Перевірені записи експортуються у `playlist.m3u8` та `data/playlist.json`.

## Локальна музика

Програма сканує `downloads/` і `music/` для відновлення шляхів, але ефірна бібліотека складається лише з треків, які вибрав AI та успішно завантажив LUMEN Downloader. Підтримуються MP3, FLAC, M4A, AAC, WAV, OGG та Opus. Старі TXT-каталоги й сторонні локальні файли можуть залишатися в SQLite як архів, але в інтерфейсі та ротації не з’являються.

Зіставлення спочатку використовує ID3/метадані `artist` і `title`, а за їх відсутності — назву файла на кшталт:

```text
001 - Three Days Grace - Human Race.mp3
```

Точні локальні збіги позначаються `LOCAL` і прив'язуються до бібліотеки. Інші аудіофайли тимчасово додаються в кінець бібліотеки за вбудованими метаданими. Плеєр відтворює тільки локальні файли через localhost і не використовує YouTube IFrame, тому заборона вбудованого аудіопотоку не впливає на ефір. Файл `links.txt` призначений для URL на матеріали, які ви маєте право завантажувати; один URL на рядок.

Динамічне поповнення працює у два етапи: AI спочатку повертає точні пари `виконавець — трек`, після чого радіо викликає той самий аудіомеханізм, що й `Start LUMEN Downloader.cmd`. Однакова назва, приписана різним артистам, відсіюється. Якщо основний список не дає точного результату, DJ перевіряє схожі треки й резерв другого провайдера. Завантажувач приймає файл лише після збігу артиста, назви та тривалості, бере `bestaudio`, за наявності FFmpeg конвертує його в MP3, а без FFmpeg залишає сумісний оригінальний аудіоформат. До бібліотеки й черги трек потрапляє лише після появи готового локального файла. Порожня бібліотека починає завантаження під час запуску, а після зменшення буфера до порога автоматично добирає нові композиції. Кнопка «Оновити AI-бібліотеку» примусово запускає новий добір. Перевірений завантажений буфер зберігається після закриття, тому повторний запуск не чекає хвилину-дві на перший трек. При зміні жанрового промпта несумісний старий буфер очищається автоматично.

## Автоматичний ефір

Під час кожного запуску перша доступна композиція вибирається випадково; останній програний трек не може стати першим знову, якщо є інші варіанти. Далі працює випадковий session shuffle-bag: уже зіграні композиції не повертаються, доки не завершиться весь доступний цикл. Заплановані треки також унікальні, тому повтор не ховається навіть усередині черги підготовки.

Типовий режим — `Random без повторів`, а ведучий говорить перед кожною піснею. Відразу після старту першого аудіотреку паралельно готуються його підводка, транскрипція назв і перший перехід `поточний → наступний`. Навіть якщо зовнішній API або попередньо підготовлений TTS не встиг, миттєвий локальний текст передається системному українському голосу замість мовчазного переходу.

Система планує кілька наступних треків і заздалегідь готує для кожної пари `поточний → наступний` текст, TTS і точний сценарій мікшування. Перший перехід стає доступним раніше, а глибші готуються слідом у фоні. У момент переходу програма бере готовий WAV або MP3 із кешу, вибирає версію, яка реально вміщується до вокалу або у виміряне аутро, і запускає події гучності. Якщо локальний StyleTTS2 не підготував звук, система пробує Edge TTS, а потім локальний системний `uk-UA` голос; текст підводки при цьому не втрачається.

`TransitionDirector` підтримує чистий стик, репліку між треками, `talk-up` до першого вокалу та голос поверх аутро. Холодні й жорсткі закінчення не перекриваються голосом. Глибина черги підготовки, імовірність репліки та гучність музики під голосом задаються в «Налаштуваннях». Ротація працює як mood-radio: `Random без повторів` або `Розумний настрій` з урахуванням енергії, історій і кількості повторів.

`ContextEngine` формує знімок саме на запланований момент переходу: частину доби, вихідний, початок години, радіогодинник, станцію, місто, поточний і наступний треки, пам'ять ведучого та повтори виконавців. Погодні штрихи необов'язкові й вимкнені за замовчуванням; після увімкнення результат кешується на 15–30 хвилин і використовується лише як фактичне джерело, без вигадування прогнозу.

`ContentPlanner` вирішує, чи потрібні час, коротка погода, mood-check, перевірений факт, музична історія, тизер або лайнер. Cooldown-и й історія останніх виходів не дають повторювати той самий хід. Факти про треки звучать лише після ручного додавання як перевірених.

Звичайна підводка орієнтується на доступний ефірний час, а не на жорстку кількість слів. Кожен AI створює один–три варіанти (типово два). Правопис, пунктуація, маркери назв, фактичні обмеження, повтори й темп перевіряються паралельно. Якщо всі перші варіанти відхилені, мовні редактори одночасно виправляють придатні чернетки. Перемагає найвищий бал якості; порядок провайдерів використовується лише при нічиїй.

## Music Story

`MusicKnowledgeBase` зберігає не один сухий факт, а перевірені Story Cards категорій `SONG_ORIGIN`, `STUDIO_STORY`, `BAND_ARGUMENT`, `LYRICS_ORIGIN`, `ACCIDENTAL_HIT`, `RECORDING_TRICK`, `LIVE_STORY`, `NAME_STORY` та інших. Картка містить hook, послідовність перевірених фрагментів, необов'язкову дослівну цитату, джерела, карту відповідності тверджень доказам, тривалість `short` / `normal` / `feature` і дані серіалу. Картку не можна позначити `verified` без повного HTTP(S) URL надійного джерела рівня A–C.

Джерела мають редакційні рівні `A`, `A-`, `B`, `B-`, `C`, `D` або `E`. Рівні D/E можна зберігати лише як чернетку. Картка з двома незалежними надійними джерелами отримує статус `corroborated` і має пріоритет у ротації; оригінальний запис, документ або інтерв'ю можна позначити як `primary_source`. Для тем війни, безпеки, жертв, медицини, виборів, фінансів або звинувачень ефірний шлюз додатково вимагає два незалежні джерела, ім'я редактора й час людського схвалення. Старі поля `source_url` і `source_title` підтримуються для сумісності як одне джерело.

Story Selector спочатку бере невикористану картку. `StoryMemory` позначає сюжет використаним лише після фактичного виходу переходу в ефір. Перевірені історії мають стовідсотковий пріоритет і плануються не рідше ніж через один перехід, доки в черзі є відповідні картки. Якщо наступний трек не має картки, перший перехід після стартової пісні може розповісти перевірену історію саме про щойно почуту композицію. Пояснення виконавця, перевірена цитата або позиція вказаного критичного джерела ставляться в центр сюжету, але система нічого не приписує їм без Story Card.

У `MUSIC STORY MODE` модель отримує тільки `VERIFIED_STORY_DATA` і не має права вигадувати діалоги, цитати, місця, дати, реакції, причини чи емоції. Без NVIDIA використовується локальний сюжет, складений лише з фрагментів картки. Додати одну картку можна кнопкою `STORY` у бібліотеці.

Для попередньо дослідженого каталогу картки імпортуються пакетом, а не створюються під час ефіру:

```powershell
.venv311\Scripts\python scripts\import_stories.py music-stories.json
```

Формат файла:

```json
[
  {
    "artist": "Artist",
    "title": "Track",
    "stories": [
      {
        "category": "SONG_ORIGIN",
        "hook": "Цю пісню могли не записати",
        "story_data": ["Перевірена деталь", "Перевірений поворот"],
        "source_url": "https://example.com/source",
        "source_title": "Interview",
        "sources": [
          {
            "id": "source-1",
            "url": "https://example.com/original-interview",
            "title": "Original interview",
            "tier": "B",
            "primary": true,
            "independent": true
          },
          {
            "id": "source-2",
            "url": "https://example.org/independent-report",
            "title": "Independent report",
            "tier": "B",
            "primary": false,
            "independent": true
          }
        ],
        "claims": [
          {
            "text": "Перевірена деталь",
            "source_ids": ["source-1", "source-2"]
          },
          {
            "text": "Перевірений поворот",
            "source_ids": ["source-1", "source-2"]
          }
        ],
        "confidence": "verified",
        "duration_class": "normal",
        "series_key": "artist-track",
        "episode": 1,
        "tease_next": "чому музиканти спочатку були проти"
      }
    ]
  }
]
```

`VoiceDirector` тримає три окремі шари тексту: авторський, мовно нормалізований та TTS-версію. Темп, довжина, кількість фраз і паузи залежать від частини доби, енергії треку та доступного вікна. Мовний стиль налаштовується, але суржик за замовчуванням обмежений низьким рівнем.

Якщо WebView не дозволить перший автоматичний звук, достатньо один раз натиснути Play — після цього автоматичний цикл продовжить роботу.

Перед TTS модуль `backend/speech_normalizer.py` підставляє перевірену вимову виконавця й назви, записує час, роки, температуру та числа словами й спрощує небезпечну для синтезатора пунктуацію. Для StyleTTS2 текст додатково проходить українське наголошування та IPA-конвертацію. Вимову конкретного треку можна один раз задати кнопкою «Вимова» в бібліотеці; надалі вона зберігається в SQLite у полях `artist_speech` і `title_speech`. Іноземні назви з низькою впевненістю позначаються як такі, що потребують перевірки; до підтвердження система віддає перевагу лайнеру або чистому переходу.

## Перевірка

Модульні тести охоплюють контекст станційного часу, cooldown-и й similarity gate, три шари тексту, нормалізацію чисел, `hit the post`, аутро/жорсткі закінчення та завчасне кешування переходу:

```powershell
.venv311\Scripts\python -m unittest discover -s tests -v
```

Реальний тест провайдерів без мокових відповідей і без завантаження аудіо:

```powershell
.venv311\Scripts\python scripts\real_provider_benchmark.py --limit 10 --intro-seconds 18 --verify-tracks
```

Наскрізна перевірка WebView запускає локальну програму, програє тестовий цикл і перевіряє підготовлену чергу:

```powershell
.venv311\Scripts\python tests\smoke_gui.py
```

## Архівний імпорт бібліотеки

Цей інструмент залишено лише для обслуговування старих даних. Імпортовані записи не входять до AI-бібліотеки та не потрапляють в ефірну ротацію.

З UTF-8 TXT або JSON-масиву:

```powershell
.venv311\Scripts\python scripts\import_library.py library-import.txt
```

Вставлення списку безпосередньо в консоль:

```powershell
.venv311\Scripts\python scripts\import_library.py --paste
```

Після останнього рядка введіть `END`. Додайте `--replace`, якщо потрібно повністю замінити бібліотеку. Без цього параметра наявні YouTube ID, підводки та статистика зберігаються.

## Формат імпорту

```text
1. Artist - Track
2. Artist - Track
```

Дані й ключі зберігаються локально у `data/radio.db`. Не додавайте цю базу до публічного репозиторію.
